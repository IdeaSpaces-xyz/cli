# CLI 0.9.0 — hosted Spaces, honest local Threads, `threads launch-text`

This release adds the hosted Space commands, makes local Threads say where each post is, and adds the CLI half of launching a session from a point in a Thread. It also changes the output of two `spaces` commands, so read the first section if a script reads them.

## What changes

**Hosted Spaces from the CLI.**

- **`spaces list --hosted` and `spaces open <map-id>` now read named Maps,** so their output differs from the legacy coordination list. Plain `spaces list` is unchanged and still shows the legacy objects; the legacy filters (`--attached-to`, `--include-dormant`) refuse with `--hosted`.
- **New:** `spaces add`, `spaces remove`, `spaces import`, `spaces export`, and `spaces new --hosted --vault <personal|person:user_ID|node:ORG_NODE_ID>`. Hosted edits are owner-only and take `--if-match` from `spaces open --json`; an exact retry keeps its `--command-id` and every argument. `spaces remove` previews until `--yes`.
- **`threads new --hosted` and `threads send` take `--home map:<id>`** to place a Thread in a hosted Space. Placement grants nothing and adds no Map member. Local Threads refuse `--home`.

**Honest local Threads.**

- **`threads open` says where each post is:** local only, committed, or pushed, read from Git with no network. `threads post` says a new post is local only. Where Git can't tell, it says unknown instead of guessing.
- **`threads check` is new.** It lists posts edited or deleted after their first commit.
- **A local author reads as `claimed by X`,** with one warning per Thread, and so do the launch frames. Nothing proves a local author.
- **Line breaks in fields a writer chose can no longer forge a line.** An author, name, summary or tags value stays on one line.

**Launching from a point.**

- **`threads launch-text <slug|path> --post <msg_id>`** prints the text a session launched from that post starts with: the post's own Map at its depths, the Note, and the Agreement with `--pov`. Local Threads only; it writes nothing. `--json` returns `schema: "ideaspaces.threads.launch-text.v1"`.
- **The `--json` shape of `threads launch-text` is the app engine's for now.** `lowered` and `cut` may change while the measurement of what a launch loads, and a review point on those two fields, are open. Read the text; don't build on those two fields yet.
- **`agent run` now counts the Map in its 16 KiB cap,** for a launch from a pinned local Thread with `--map`. It does not cut or drop members. The Map takes the room the Agreement and the Thread frame leave, up to its 12,000 characters, and reads its last member at a lower depth first, then the one before it, and never cuts a member mid-way. `agent run` does not list what it lowered; `threads launch-text` does, in `lowered` and `cut`. It refuses only when the Map cannot fit even with every member at name, and then it says how many bytes were left for it. As before, it also refuses when the Agreement and the Thread frame alone pass 16 KiB. A hosted Thread with `--map`, and a Space-only `--map` launch, are not counted against the cap; that is unchanged.
- **A post that is both the Note and a Map member is no longer loaded twice.**

**Windows.**

- Local path aliases match, so the same folder under two spellings is the same Space.
- The Claude and Pi launchers that npm installs (`.cmd` shims) are found and run without evaluating batch text.

## If this affects you

- A script that reads `spaces list --hosted --json` or `spaces open --json` gets Map-shaped output; read the new fields, don't assume the legacy ones.
- A script that parses `threads open` text output sees each post's location on its line. `threads open --json` adds a `state` to each post and a summary for the Thread; the fields it had stay.
- A script that parses a local author as a bare name sees `claimed by X`.
- Update to use any of this. 0.8.2 has none of the new commands.
