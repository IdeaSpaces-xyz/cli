# CLI 0.7.0 — one hosted Thread store

Prepared for release; publication still needs its own go. This change does not publish or tag.

Hosted list, open/read, new/send, post/reply, close and rename now use `/threads` alone.
Old ported 24-hex and new 32-hex `x_` ids are passed unchanged; old `n_` post ids are not
converted. Read a ported Thread to obtain its `msg_` reply parents. `ack` stays explicit.

- Default `threads list --new` or `--unread` drains every hosted page and keeps the web's
  `unread_count`; local rows use their local reader cursor. `list <directory>` stays local.
  `list --hosted --limit N --cursor C --unread` is one page; even an empty filtered page can
  have another cursor. The default drain refuses visibly after 100 pages instead of claiming
  complete Unread on a looping or exceptionally large account; use explicit hosted paging.
  Reads never acknowledge.
- Hosted new accepts `--recipients` (@handles or emails, comma-separated); send is its
  single-recipient alias. Omit recipients for a solo Thread. New/post accept an authored
  Map; each member needs its observed `disclosure`, never fabricated from curated labels.
- Reply requires explicit `--reply-to msg_…`. Close previews, then `--yes` appends a closure
  Note; copy the printed `--post-id` into confirmation. Rename appends a reframe Note with
  `--name`, `--summary`, `--message`. These use the service's write permission, not exchange
  owner-management routes. Closed Threads cannot be reopened.
- `threads capabilities --json` lets integrations verify `/threads`-only transport before
  any hosted request. MCP and Pi refuse a stale or overridden CLI rather than letting a
  ported id silently fall back to exchanges.

## Breaking removals and JSON change

The `inbox` alias, `threads posts` feed, `threads expand` bound Map expansion and `threads add`
exchange-owner control are removed. Manage membership on the web. Cross-Thread and follow/mute
feeds, hosted child discovery, reopening and owner-default routing are not rebuilt. Access
requests remain under `request incoming`, separate from Threads.

`map select --json` now returns `{roots, members}` directly, not the retired
`{kind: "exchange-map-selection", target_node_id, map}` envelope. Its pinned read-only
selection checks remain. Consumers that parsed `.map` must use the returned object itself;
there is no recipient or implicit owner route in its output.

MCP, Pi and Claude plugin have coordinated consumer changes. Their release artifacts must
pin merged CLI/MCP inputs. A merge does not update installed copies, and server removal must
wait for the human-authorized client releases.

## Evidence boundary

Unit and command tests cover both id lengths, page draining, repeated-cursor refusal,
Unread filtering, recipient/Map opening, explicit reply parents, close/reframe Notes,
local-prefix paths and bounded large-post launch references. Loopback API evidence uses
synthetic auth and an isolated SQL store, never production accounts. Final delivery records
the exact tested head and CI result; preparation is not a release claim.
