# CLI 0.7.0 — one hosted Thread store

Never published on its own. This text reached people in [0.7.1](0.7.1.md), released 2026-11-04.

Hosted list, open/read, new/send, post/reply, close and rename now use `/threads` alone.
Hosted `x_` ids are opaque: the CLI checks `x_` and the service's characters, never a length, so
old ported 24-hex and new 32-hex ids pass unchanged, as does whatever the service mints next. Old
`n_` post ids are not converted. Read a ported Thread to obtain its `msg_` reply parents. `ack` stays explicit.

- Default `threads list --new` or `--unread` drains every hosted page and keeps the web's
  `unread_count`; local rows use their local reader cursor. `list <directory>` stays local.
  `list --hosted --limit N --cursor C --unread` is one page; even an empty filtered page can
  have another cursor. `--limit` and `--cursor` require `--hosted`; they never silently
  switch a combined list into hosted-only. The default drain refuses visibly after 100 pages instead of claiming
  complete Unread on a looping or exceptionally large account; use explicit hosted paging.
  Reads never acknowledge.
- Hosted new accepts `--recipients` (@handles or emails, comma-separated); send is its
  single-recipient alias and refuses a second `--recipients` input. Omit recipients for a solo Thread. New/post accept an authored
  Map; each member needs its observed `disclosure`, never fabricated from curated labels.
- Reply requires explicit `--reply-to msg_…`. Close previews, then `--yes` appends a closure
  Note; copy the printed `--post-id` into confirmation. Rename appends a reframe Note with
  `--name`, `--summary`, `--message`. These use the service's write permission, not exchange
  owner-management routes. Closed Threads cannot be reopened.
- `threads capabilities --json` lets integrations verify `/threads`-only transport before
  any hosted request. MCP and Pi refuse a stale or overridden CLI rather than letting a
  ported id silently fall back to exchanges.

## Breaking removals and JSON change

The `inbox` alias, `threads posts` feed, `threads expand` bound Map expansion and `threads add`
exchange-owner control are removed. Manage membership on the web. Cross-Thread and follow/mute
feeds, hosted child discovery, reopening and owner-default routing are not rebuilt. Access
requests remain under `request incoming`, separate from Threads.

`map select --json` now returns `{roots, members}` directly, not the retired
`{kind: "exchange-map-selection", target_node_id, map}` envelope. Its pinned read-only
selection checks remain. Consumers that parsed `.map` must use the returned object itself;
there is no recipient or implicit owner route in its output.

MCP, Pi and Claude plugin have coordinated consumer changes. Their release artifacts must
pin merged CLI/MCP inputs. A merge does not update installed copies, and server removal must
wait for the human-authorized client releases.

## Evidence boundary

Unit and command tests cover both id lengths, page draining, repeated-cursor refusal,
Unread filtering, recipient/Map opening, explicit reply parents, close/reframe Notes,
local-prefix paths and bounded large-post launch references. Loopback API evidence uses
synthetic auth and an isolated SQL store, never production accounts. Final delivery records
the exact tested head and CI result; preparation is not a release claim.

Local creation continues to allow letters, digits and hyphens only, so it cannot mint an
`x_` name. An existing folder of exactly that name in `_threads/` stays local and wins over the
service; any other bare `x_` name is read as a hosted id, so an `x_` slug with no folder here now
reports the service's answer rather than a missing local Thread.

`--kind` takes only what a reader acts on: `post`, `snapshot`, `reframe`, `correction`, `closure`,
`mark`. `decision`, `dispatch`, `claim`, `delivery`, `verification` and `question`
are no longer kinds, and `--yes` no longer opens a custom kind: `--kind delivery`
is refused and names `--tags`. A label goes in `--tags`, in a folder or on the service (`threads post
x_<id> --tags delivery`, `threads new --hosted`, `threads send`); hosted tags travel in the Note's
frontmatter. Every existing post still reads, including any custom kind. `threads close x_<id> --yes`
is a different confirmation and stays.

`threads recent` says which local Threads moved since a position: ids and counts only, from the set
of post files, so a post merged in with an old date is not lost. Hold the cursor yourself, or name a
reader with `--reader` or `IDEASPACES_READER`; the default is the person, never the working folder.
A first look sets a baseline; only `threads ack --recent <cursor>` moves a held position. Hosted
Threads are not in it yet (`hosted_checked: false`). `threads ack <slug> --through <post-id|latest>`
is a local read position, and `--reader` on `list --new` and `open --new --ack` keeps each reader's
apart. `threads list` now sorts by latest activity, so anything reading its JSON in order sees a
new order; `--open` leaves closed Threads out. A `name` read no longer lists the Space's skills,
and its JSON `reference.skills` is empty.

The person’s CLI `threads ack` remains. Agent-facing MCP/Pi tools intentionally omit ack
until an agent has its own token and cursor; they must not advance the person’s Unread.

`follow thread` / `unfollow thread` are retired rather than pointed at the old exchange
store; hosted Thread Unread needs no follow subscription. Node/repo subscriptions are
unchanged and are not a hosted Thread feed. A degraded default list can return local rows
with `hosted_checked:false`; with `--new`/`--unread` it exits 1 so automation cannot treat
an incomplete account Unread query as success.
