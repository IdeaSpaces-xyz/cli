# CLI 0.8.2 — a first message to someone new is a knock

On the service, a first message to someone new becomes a knock. This release lets the CLI say so. 0.8.1 prints "Opened" for a knock, and calls a knock that's already open an unreadable answer, so update before you reach someone new.

## What changes

- **`threads new --hosted` and `threads send` print a knock as a knock:** `Knocked on @handle`, under the name the service gives it, not "Opened". Neither of you can post until they let you in, and they answer on the web.
- **A knock already open is said plainly.** Your new message isn't stored, and they still see your first one.
- **`--json` adds `reach` to the answer,** `knocked` or `direct`. An older service leaves it out, so read it as possibly absent. On a knock, `message_stored` says whether this message was the one kept, and `post` is the knock's first post.
- **Refusals say what happened.** A new person among several recipients, a Map on a first contact, a message over 1,000 characters, a knock limit, an unknown `@handle` and posting in an unanswered or lapsed knock each say so and say what to do. When a limit is reached, the wait is in the message. These refusals stored nothing, so they no longer say the post may have landed.
- **A refusal this CLI doesn't know shows the service's words,** on 403, 409 and 429 as well as 400.
- **`threads open` takes `can_reply` from the service** when it sends one, and the grade still answers for an older service. A knock shows its state on the status line. On a knock waiting for you, it says to answer on the web: the CLI can't let anyone in.

## If this affects you

A script that reads `threads open --json` gets `thread.knock` on a knock, and `thread.can_reply` is now the service's answer, so it can be `false` on a Thread you own. A script that reads `--json` errors gets the same `state` values, with new words in `message`.
