# CLI 0.8.1 — a stored key stays with its service

A security fix, and the one change in this release.

A stored credential now goes only to the service it was saved for. Stored sessions already worked this way, but a stored API key would follow `IS_API_URL` to any server. It no longer does: the CLI refuses, sends nothing, and says why.

## If this affects you

You are affected only if you have a stored API key and also set `IS_API_URL` to a different server, such as a local one. Commands there will now say your stored sign-in was not sent.

To keep using that server, name the pair yourself:

```sh
IS_API_URL=http://localhost:8000 IS_API_KEY=<a key for that server> ideaspaces repos
```

To use your stored sign-in, unset `IS_API_URL`. Nothing else changes. An `IS_API_URL` that matches your stored service still works, and `IS_API_KEY` behaves as before.

There is nothing to rotate unless you ran the CLI with `IS_API_URL` pointing at a server you don't control.
