# CLI 0.8.0 — see your version, update it, hear when it is behind

An old CLI could stop you with no way to see which version you had, and nothing had told you a new one was out. This release fixes that from here on. Copies older than 0.8.0 have none of this, so update once by hand:

```sh
npm install -g @ideaspaces/cli@latest
```

## What's new

- **`ideaspaces --version`** prints the version and exits 0. `-v` does the same, and `--json` gives `{"version": "0.8.0"}`.
- **`ideaspaces upgrade`** updates this CLI. It works out how this copy was installed. An npm global install is updated in place, after checking that the npm on your PATH owns this copy. Any other copy is left alone, and the command names what to run. `--check` reports and changes nothing. `upgrade` installs at once and takes no `--yes`.
- **`ideaspaces update` is unchanged.** It still brings source changes into a fork. Its `--help` now points to `upgrade`.
- **The out-of-date message says what to do.** It gives what you have, the latest as of the last check, and what to run for your install. It also now appears where it was missing: on hosted Threads, which said to try later, and at sign-in, which said to check your connection.
- **A quiet notice.** See below.
- **`status doctor`** says when this CLI is behind, from what the last check found. It makes no network call of its own. `--json` gains `checks.cli`, with `state` of `current`, `behind` or `unchecked`, plus `latest` and `install`. It is optional, so readiness and the exit code don't change.

## The update check

Once a day, a global install at a terminal checks the npm registry in the background. If a newer version is out, a later command prints one line on stderr. The first run after a release prints nothing.

This is the one network call the CLI makes on its own, and it can follow local commands too. `upgrade` and `upgrade --check` read the registry when you run them. It reads the package's public version and sends nothing about your work. It is silent with `--json` or `--quiet`, when either output is piped, in CI, in an app or agent session, and for any copy that isn't your own global install. It writes `~/.ideaspaces/update-check.json`.

To turn it off, set `IDEASPACES_NO_UPDATE_CHECK=1` or `NO_UPDATE_NOTIFIER=1`.

The daily check only ever reads `registry.npmjs.org`. `upgrade` and `--check` also follow `npm_config_registry` when you set it in the environment. None of them read `.npmrc`, so behind a mirror the version they report can differ from what `npm install` gives.
