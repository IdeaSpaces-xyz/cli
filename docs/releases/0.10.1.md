# CLI 0.10.1 — Maps on hosted posts, and one Map rule for launches

This release makes a hosted post's Map checked on the way out and visible on the way in, and makes `threads launch-text` read the same current Map the protocol defines. It also carries the two fixes made after 0.10.0.

## What changes

**A hosted `--map` is checked as a local one is.** `threads new --hosted`, `threads send` and `threads reply` now refuse a Map with an unpinned root or a position that has no depth, before any request, and say which member. The service's own rules still apply on top (an authored `disclosure` on every member).

**`threads open x_…` shows a post's Map.** Under the post's text, each member's place (root and commit, or address), its depth and what its author disclosed. The words are the author's, not the note's, and naming a place grants no access to it; nothing in the Map is fetched. `--json` carries the Map under `posts[].fields.map`.

**`threads launch-text` reads the current Map.** It used the newest snapshot that carries a Map; it now uses the Map of the newest post that carries one, of any kind, else the opening post's. For a Thread where a later reply or delivery carries a Map, the launch now stands on that one. In its JSON, `map_post.origin` is `post` (it was `snapshot`) or `opening`, and `map_post.kind` names the post's kind.

**Fixed since 0.10.0**
- `map add … --if-match <sha>` is accepted again. 0.10.0 refused it as an unknown flag.
- The CLI installs as a git dependency again (`npm install github:IdeaSpaces-xyz/cli#<commit>`). 0.10.0's build failed in a copy with no Git history.

## Installing

```sh
npm install -g @ideaspaces/cli@0.10.1
```

The CLI needs Node 20 or newer. The Claude plugin, Pi package and Desktop carry their own CLI pins; installing this npm release does not update them.
