# CLI 0.5.0 — sign in to this install

`ideaspaces login` now signs in this CLI install through your browser (`client=cli`),
with a short-lived access token and rotating refresh instead of a new long-lived
CLI Login key. Manage this install in the web's **Desktop sign-ins** list.

- API calls and Git refresh the session safely. If a rotation's outcome is unknown,
  sign in again: the CLI never blindly replays a consumed refresh.
- `ideaspaces status account --json` checks the session online. Offline is not signed out.
- `ideaspaces power logout` signs the session out on the server before clearing local
  credentials; if it cannot finish, it keeps them so you can retry.
- Storage stays in the CLI credentials file: atomic replacement, 0600 on POSIX;
  Windows inherits the existing directory ACL. This is not OS-keychain storage.
- Existing authorized API keys, including explicit `IS_API_KEY`, still work until
  revoked. Browser sign-in needs access to this CLI's loopback callback; headless/CI
  uses an existing authorized key, and SSH needs explicit loopback forwarding.
- Login replaces the saved credential. Sign out first when switching accounts/services.

Install: `npm install -g @ideaspaces/cli@0.5.0` (Node 20+ and Git).

## Consumer handoff

Publication is approved for the standalone CLI. It does not silently update bundled
clients, retire legacy server starts, or open a Claude Code plugin release batch.
Update the bundled CLI **before using fresh session sign-in**: old bundles cannot
refresh the new sessions or complete server sign-out.

Parity checked for this cut:

| Consumer | Decision / follow-up |
|---|---|
| MCP server | Existing `is_auth` shells `login` / `power logout`; no new tool. Use the released CLI through the normal CLI selection/bundled route. |
| Skills | Command names unchanged. Pi and Claude plugin `is-publish` still use a credentials-file presence check. Their next integration/batch must replace it with `status account --json`, distinguish offline from signed out, and teach server logout/retention. |
| Pi integration | Version 0.1.44 still pins CLI commit `75efa91f` (0.2.21). Integrator owns a pin/lock/version and auth-guidance update with the next Pi change; unchanged in this standalone cut. |
| Claude Code plugin | Still vendors CLI commit `b28461d` (0.4.0). Integrator owns reproducible re-vendoring, auth-guidance updates and a plugin version bump **when the human opens the batch**; unchanged here. |

Desktop's sign-in/keychain work is separate and unchanged. Its owner must update its
bundled route on that track; this release makes no Desktop rollout claim. See
[sign-in proof and rollout](../client-signin.md) for the safety contract and manual proof.
